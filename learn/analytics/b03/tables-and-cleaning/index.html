Excel tables and cleaning data

Turn a range into an Excel table, so that formulas refer to columns by name and grow with the data; sort, filter and validate it; and clean an imported export with TRIM, VALUE, DATE and the dynamic array functions, keeping the raw data untouched and every step on record.

About 70 minutes

Before you start

You will be able to

  • Build an Excel table, and write structured references, calculated columns and a total row.
  • Use sorting, filtering, data validation and Remove Duplicates, and explain what each one does to the data.
  • Clean imported text, numbers and dates with TRIM, CLEAN, PROPER, SUBSTITUTE, VALUE, DATEVALUE and DATE, keeping the raw data untouched and logging each step.
  • Choose between formulas, Text to Columns, Flash Fill, Find and Replace and Power Query for a cleaning job.
  • Use UNIQUE, SORT, SORTBY and FILTER, and explain spill ranges and the #SPILL! error.

The idea

Fictional case

Ana’s order workbook holds the 231 cleaned spring orders as a plain range, A1:M232. Every month she pastes new orders underneath, and then has to stretch every formula, every SUM range and every chart to reach the new rows; twice she has forgotten one and reported a total that stopped at June’s first week. Each month’s orders also arrive as a raw export from the shop platform, with the same untidy text, prices and dates that B02 cleaned, and she cleans them again by hand.

An Excel table solves the first problem. It is a range that Excel manages as one object, with a name, a header row, and columns that formulas can refer to by name. To make one, click any cell in the data and choose Insert › Table, or press Ctrl+T (Ctrl+L also works; on a Mac, ⌘+T or Control+T), and confirm that the table has headers. Excel names it Table1; give it a better name in the Table Design tab (Table on a Mac) › Table Name. Ana calls hers Orders.

Table names have rules: they start with a letter, an underscore or a backslash, contain no spaces (use an underscore or a full stop), run to at most 255 characters, can’t look like a cell reference such as Z100, and must be unique in the workbook, ignoring capitals. Three things change as soon as the range is a table. Filter buttons appear on every header. Typing or pasting in the row directly below the table, or the column to its right, makes the table grow to include it. And formulas can name columns instead of cell ranges.

The same formulas written with cell references and with structured references

A structured reference such as Orders[order_total] means “the data in the order_total column of the Orders table”, however many rows that is today. When July’s orders are pasted under the table, =SUM(Orders[order_total]) includes them, while =SUM(J2:J232) stops at row 232. Structured references are also easier to read: a reviewer can see what =SUMIFS(Orders[order_total],Orders[channel],"app") adds up without opening the columns.

The second problem, cleaning the raw export, needs a workflow rather than a feature. B02 set its rules: keep the raw data exactly as received, build the cleaned version from it by steps that can be repeated, and record each step in a cleaning log. In Excel that means a raw sheet nobody edits, a cleaning sheet whose columns are formulas pointing at it (or a Power Query that does the same), and a table of the clean result that the analysis reads.

Key idea: Never clean in place

Every edit typed over the raw data is a step nobody can see or repeat. Clean with formulas or recorded query steps that point at an untouched raw sheet, check the result, and log what each step did. Next month, paste the new export into the raw sheet and the clean version rebuilds itself.

In depth

Structured references

Excel writes structured references for you: start a formula, click a cell or a column of the table, and the reference appears by name. You can also type them. Inside the table, a reference to the same row needs no table name; outside it, name the table.

The forms you will use most (table Orders)
ReferenceMeans
Orders[order_total]The data rows of the order_total column
[@quantity] or Orders[@quantity]The quantity in the same row as the formula (Excel writes @ for “this row”)
OrdersAll the data rows of the table
Orders[#Headers], Orders[#Totals], Orders[#All]The header row; the total row; the whole table including both

Structured references adjust themselves: when rows are added or removed, the column references cover the new extent, and when you rename a column or the table, Excel updates every formula in the workbook that uses it. Copying a formula keeps its structured references exactly as written. Filling a fully qualified reference across, as Microsoft puts it, adjusts the column specifiers “like a series”, so Orders[quantity] filled one column to the right becomes Orders[unit_price], the next column’s name.

Calculated columns and the total row

Type a heading in the empty column to the right of a table and the table widens to include it. Type a formula in one cell of that column, press Enter, and Excel fills it down the whole column: a calculated column. Rows added later receive the formula too, so the column never has a gap. Ana’s first calculated column checks every order’s arithmetic, the B02 cross-field check written as a formula: =[@order_total]-([@quantity]*[@unit_price]-[@discount]) should be 0 in every row.

The total row is switched on with Table Design › Total Row. Each cell in it has a drop-down of summary functions, and the defaults use SUBTOTAL: the sum of a column is written =SUBTOTAL(109,[order_total]). SUBTOTAL’s first argument chooses the calculation and what to do with hidden rows: 9 sums including rows you have hidden by hand, 109 sums excluding them, and both always leave out rows hidden by a filter. SUBTOTAL also ignores other SUBTOTALs inside its range, so subtotals are never counted twice.

That makes the total row a live summary of whatever the filter shows. Filter Orders to the app channel and the total row shows the app orders’ value, while =SUM(Orders[order_total]) elsewhere still shows all 231 orders. Neither is wrong; they answer different questions, so label them.

Sorting and filtering

Sorting rearranges rows: Sort A to Z or Sort Largest to Smallest on a column, or several levels at once with Data › Sort and Add Level. Sort whole records, never one column on its own: sorting part of a range separates the sorted cells from the rest of their records, and when Excel notices that you have selected only part of the data it offers to expand the selection, which you should accept. A table always sorts whole rows. If the original order matters (the order the export arrived in, say), keep an id column you can sort back by.

Filtering hides the rows that don’t meet a condition; nothing is deleted. A table has filter buttons on its headers already, and a plain range gets them from Data › Filter. Each button offers text, number or date filters to suit the column, such as channel equals app, order_total greater than 35, or order_date in May. Pair a filter with SUBTOTAL, not SUM, when the total should follow what you see.

Data validation

Data validation (Data › Data Validation) restricts what can be typed into cells. It guards new entries: B02’s validation rule checks data that already exist, while Excel’s data validation stops some errors at the moment of typing. Its Settings tab allows whole numbers, decimals, a list, dates, times, a text length or a custom formula, each with a condition.

Rules Ana sets on the columns of her manual-order sheet

An Input Message tab shows a hint when the cell is selected. The Error Alert tab chooses the response to a bad entry: Stop prevents it, Warning warns but lets the user keep it, and Information is the most lenient, letting the user accept or reject the value. Two limits matter. Microsoft notes that validation shows messages and blocks entries only when data are typed directly into a cell, so pasting or filling can bring invalid values in. And adding a rule to cells that already hold data doesn’t flag the bad ones; Data Validation › Circle Invalid Data marks them.

Remove Duplicates

Data › Remove Duplicates deletes rows that repeat values in the columns you tick. Microsoft lists its rules: it keeps the first occurrence and deletes the others; it compares what appears in the cells, not the underlying value; it removes whole rows even though only the ticked columns are compared; and the deletion is permanent apart from Undo. Work on a copy, and count before you delete: =COUNTIF($A$2:$A$21,A2) filled down counts each id’s occurrences (a conditional aggregate), so any count above 1 marks a repeated id.

Which columns to tick is a business decision, the one B02’s duplicates lesson calls the business key. Ticking every column removes only exact duplicates, such as order LC-10003, which appears twice in Lantern’s raw export with identical values. Ticking only order_id would also delete an updated version of an order, keeping whichever came first rather than the one that is right.

Cleaning Lantern’s raw export, step by step

The first 20 rows of B02’s raw export show the usual problems. Every price and total arrived as text, 13 of the 20 prices with a dollar sign; 18 dates are ISO 8601, 1 is written out and 1 is a slash date; one email has a stray leading space and capitals; order LC-10003 appears twice; 6 ratings are blank; and LC-10016’s total doesn’t equal quantity × price − discount.

ratingBlank: no rating givenLeave blank; never turn it into 0

TRIM removes every space except single spaces between words, but only the ordinary space character (code 32): the non-breaking space (code 160) that web pages use survives it, and needs =TRIM(SUBSTITUTE(A2,CHAR(160)," ")). CLEAN removes the non-printing control characters with codes 0 to 31. PROPER capitalises the first letter and every letter that follows a non-letter, and lowers the rest, so it turns “house blend 250g” into “House Blend 250G”: harmless for a lookup, which ignores case, but check its output before you publish it.

VALUE converts text that looks like a number, date or time in a format Excel recognises: =VALUE("$1,000") is 1000, and arithmetic such as =I2*1 converts the same way. SUM does not: it skips text, as B02 showed. After converting, =COUNT(L2:L21) should equal the number of rows; any shortfall is a value that failed to convert and needs a look.

Dates need the most care. DATEVALUE converts date text to a serial number, and Microsoft warns that the computer’s system date setting can change its results, so the same text can give different dates on different machines. With US settings, “05/03/2026” becomes 3 May 2026, silently. B02 established that Lantern’s web shop writes the day first, so this order was placed on 5 March; =DATE(RIGHT(B2,4),MID(B2,4,2),LEFT(B2,2)) builds the date from its parts in the order you decide, and gives the same answer everywhere. Use DATEVALUE only for unambiguous text (ISO dates, written-out months), and test a few results against the source.

Each step goes in the log, B02-style: what the column does, the rule, and the count it affected. For example: “unit_price: VALUE of the raw text; 20 of 20 converted.” “order_date: DATEVALUE for ISO and written dates (19 rows), DATE from parts for day-first slash dates (1 row).” “LC-10003: exact duplicate, second copy removed; 20 rows become 19.” “LC-10016: total disagrees with its parts by $6.50; set to $14.85, as B02 decided.”

Power Query is the tool built for the monthly export. It connects to the data, transforms it, can combine it with other sources and loads the result to a worksheet, leaving the original source unchanged. Each transformation appears in the editor’s Applied Steps list, where steps can be renamed, deleted, edited or reordered, and when the query is refreshed each step runs again automatically: a cleaning log that executes itself. Microsoft states that it is available in every stand-alone version of Excel for Windows from Excel 2016, and on a Mac to Microsoft 365 subscribers. This lesson stays with formulas, which work everywhere and show their logic cell by cell; B07 SQL returns to the same steps as queries.

Dynamic arrays: UNIQUE, SORT, SORTBY and FILTER

The lookups lesson showed a formula that returns several values and spills them into neighbouring cells. Four dynamic array functions make that their job. Excel draws a border round the spill range while you select it, only the top-left cell can be edited, and the range grows or shrinks by itself when the source changes. Pointed at a table column, they keep up with the table.

Four functions that spill, on Lantern’s Orders table
FunctionExampleResult
UNIQUE(array, [by_col], [exactly_once])=UNIQUE(Orders[region])The 5 regions, each once
SORT(array, [sort_index], [sort_order], [by_col])=SORT(UNIQUE(Orders[region]))The 5 regions from Central to West
SORTBY(array, by_array1, [sort_order1], …)=SORTBY(Orders[order_id],Orders[order_total],-1)All 231 ids, largest order first (LC-10144)
FILTER(array, include, [if_empty])=FILTER(Orders[order_id],Orders[order_total]>100,"none")The 6 orders over $100

FILTER’s include argument is a column of TRUE and FALSE values as tall as the array. Multiply conditions for AND and add them for OR: =FILTER(Orders,(Orders[region]="Central")*(Orders[channel]="web")) keeps Central’s web orders, all columns. If nothing qualifies and if_empty is left out, FILTER returns #CALC!, because Excel has no empty array. UNIQUE’s exactly_once set to TRUE keeps only values that occur once, and wrapping UNIQUE in ROWS counts the distinct values: =ROWS(UNIQUE(Orders[customer_id])) gives 112 customers.

A spilled formula fails with #SPILL! when it can’t spill. The usual causes are these: the spill range isn’t empty (delete or move whatever is in the way), the formula is inside a table (spilled array formulas aren’t supported in tables, so put it beside the table), the result would run off the edge of the sheet, or it would spill into merged cells. To refer to a whole spill range, put # after its first cell: if D2 holds =SORT(UNIQUE(Orders[region])), then =COUNTA(D2#) counts what it spilled, however many rows that becomes.

Standards: Which versions have dynamic arrays

UNIQUE, SORT, SORTBY and FILTER work in Excel for Microsoft 365, Excel 2024 and Excel 2021, on Windows and on Mac. The spilled range operator (#) is documented for Excel for Microsoft 365. In Excel 2019 and earlier these functions don’t exist: use filters and sorting instead, and to count distinct values either a helper column such as =COUNTIF($C$2:C2,C2)=1 (TRUE at each value’s first appearance) counted with =COUNTIF(D2:D232,TRUE), or a PivotTable’s Distinct Count.

Common mistakes

  • “A table is just formatting.”

    The banded rows are the least of it. A table has a name, grows when rows are added, fills calculated columns and lets formulas say Orders[order_total] instead of a range that has to be stretched by hand. Ranges that stop short are one of the commonest causes of a wrong total.

  • “The total row and SUM give the same total.”

    Only when no filter is on. The total row uses SUBTOTAL, which leaves out rows hidden by a filter; SUM counts every row. Decide which the reader needs and label it.

  • “Data validation keeps the column clean.”

    It blocks bad values typed into a cell, not values pasted or filled in, and it doesn’t flag data that were already there. Use Circle Invalid Data after adding a rule, and keep checking imported data with formulas.

  • “DATEVALUE converts the dates.”

    It converts them using the computer’s date settings, so a day-first slash date such as 05/03/2026 becomes 3 May on a US-settings machine without any error. Build ambiguous dates with DATE from their parts, in the order the source used.

  • “I’ll fix the export in place; it’s quicker.”

    Edits typed over the raw data can’t be checked, repeated or undone next month. Keep the raw sheet untouched, clean with formulas or Power Query steps, and log each step.

  • “#SPILL! means the formula is wrong.”

    It usually means the formula is fine but has nowhere to put its results: something sits in the spill range, or the formula is inside a table. Clear the range or move the formula beside the table.

Summary

  • An Excel table (Ctrl+T) has a name, grows with its data, and lets formulas use structured references such as Orders[order_total] and [@quantity].
  • A calculated column fills one formula down the whole table, including rows added later; the total row uses SUBTOTAL, which leaves out rows hidden by a filter.

Terms introduced

Excel table
A range that Excel manages as one named object, with a header row, filter buttons and columns that formulas can refer to by name; it grows when rows or columns are added next to it.
Structured reference
A reference to part of an Excel table by its table and column names, such as Orders[order_total], or [@quantity] for the value in the formula’s own row.
Calculated column
A column of an Excel table filled by one formula, which Excel copies to every row, including rows added later.
Total row
An optional last row of an Excel table that summarises its columns, by default with SUBTOTAL so that rows hidden by a filter are left out.
Data validation
An Excel feature that restricts what can be typed into cells (a list, a range of numbers or dates, a text length or a formula) and shows an input message or an error alert.
Dynamic array function
A function, such as FILTER, SORT, SORTBY or UNIQUE, that returns several values which spill into the neighbouring cells; available in Excel for Microsoft 365, Excel 2021 and Excel 2024.
Power Query
Excel’s tool for importing and reshaping data (Data › Get & Transform Data), which records each transformation as a step and reruns all of them when the query is refreshed.
