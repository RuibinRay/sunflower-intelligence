PivotTables

Summarise hundreds of rows by dragging fields: order value by month and channel, events by type, each item’s share of a total. Learn how a PivotTable groups and aggregates its source, how to show percentages and months, how to keep it up to date, and when SUMIFS formulas are the better choice.

About 70 minutes

Before you start

You will be able to

  • Prepare source data for a PivotTable, and explain why an Excel table is the best source.
  • Build PivotTables with fields in the Rows, Columns, Values and Filters areas, choosing Sum, Count, Average, Max or Min.
  • Use Show Values As to give percentages of the grand total, the column total and the row total, and interpret each correctly.
  • Use date grouping, sorting and filtering on a PivotTable, and refresh it after its source data change.
  • Compare a PivotTable with SUMIFS and COUNTIFS formulas, reconcile one against the other, and choose the right tool for a report.

Review first

  • Conditional sums, counts and averages — Every cell of a PivotTable is a conditional sum or count; SUMIFS and COUNTIFS are how you check one.
  • Excel tables and cleaning data — A PivotTable should be built on an Excel table of clean data.
  • Transforming and reshaping data — Aggregation, and the reshaping B02 calls a pivot, are what a PivotTable does.
  • Summarising data: changes, averages and spread — Choosing a sum, a count or an average depends on the question, as B01 explains.

The idea

Fictional case

Ana wants to know how the spring’s $9,096.15 of online orders moved from month to month, and how much of it came through the app. With SUMIFS she would write a grid of formulas, one per month and channel, and rewrite it the moment she asked the next question: by region instead, or only for subscriptions. She needs a summary she can rearrange in seconds, built from the Orders table.

A PivotTable is Excel’s interactive summary of a list of records. It groups the records by the values of the fields you place in its rows and columns, and in each cell aggregates a field you choose: the sum of order_total, the count of orders, the average invoice. B02 used “pivot” for reshaping long data into a wide table and defined aggregation as combining many values into one; a PivotTable does both at once, and redoes them every time you move a field.

To build one, click a cell in the table and choose Insert › PivotTable, check the source (the table Orders) and choose a new worksheet. The PivotTable Fields pane lists each column header of the source as a field, and below it are four areas. Fields in Rows become row labels down the left; fields in Columns become column headings across the top; fields in Values are summarised in the body; and fields in Filters become report filters above the table. Tick a field and Excel places it for you: Microsoft notes that non-numeric fields usually go to Rows and numeric fields to Values. Drag a field to move it.

Read the result as a set of conditional aggregates. The May and web cell, $2,159.05, is the total of order_total over the orders placed in May through the web shop: exactly what =SUMIFS(Orders[order_total],Orders[channel],"web",Orders[order_date],">="&DATE(2026,5,1),Orders[order_date],"<"&DATE(2026,6,1)) computes. The PivotTable writes every such cell at once, adds the row and column totals, and rebuilds them all when Ana swaps channel for region.

The first view already raises a question. May has the most order value, $2,929.75, but the fewest orders, 49. A sum can’t say why; the records can. One web order in May, LC-10144 on 14 May, was the 120-bag office order worth $1,512.00: without it May’s value would be $1,417.75, the lowest of the four months. A PivotTable is the fastest way to find where a total comes from, and the start of the questions, not the end.

Key idea: Every value cell is a SUMIFS

Each cell in the body of a PivotTable aggregates the records whose fields match that cell’s row label, column label and filters. That is why a PivotTable and a SUMIFS or COUNTIFS formula over the same table must agree, and why checking one against the other is the standard test of both.

In depth

Source data a PivotTable can use

Microsoft’s advice for source data comes down to the shape B01 called structured data: one record per row and one field per column.

  • A single header row of unique, non-blank labels, one per column. Two header rows, or a blank heading, leave a field without a usable name.
  • Records in rows, fields in columns. A sheet with one column per month is already a summary; reshape it into rows of month and value first (B02’s transforming-data lesson).
  • One type per value field. Don’t mix text and numbers in a column you will sum.
  • No totals inside the data. A subtotal row typed between the records would be summed with them and counted twice.
  • Ideally an Excel table. The table grows when rows are added, so the PivotTable sees them at the next refresh.

Values: Sum, Count, Average and the rest

Right-click a value and choose Summarize Values By to pick the aggregation: Sum, Count, Average, Max, Min, Product, StdDev, StdDevp, Var or Varp (the last four belong to B04). A numeric field in Values starts as Sum. Microsoft states the rule for the exception: if the field contains blanks or non-numeric values (text, dates or Booleans) when you place it in Values, the PivotTable uses Count. So a column of order totals stored as text arrives as “Count of order_total”, and a cleaning problem shows up as a summary problem.

Count counts non-empty values, as COUNTA does, not records. Lantern’s rating column is blank for orders that weren’t rated, so Count of rating gives 154, not 231; to count orders, count a field that is never blank, such as order_id. Average ignores blanks the same way: the average rating, 4.10, is the average of the 154 ratings given, and says nothing about the 77 orders without one.

Several summaries can sit side by side: drag order_total into Values twice and set one to Sum and one to Average. By channel that gives $3,656.20 and an average order of $36.93 for the app, against $5,439.95 and $41.21 for the web shop, the average order value of each.

Counting different things is another matter. Count of customer_id counts orders (231), not customers. Microsoft’s Distinct Count summary counts each value once, but it works only when the PivotTable uses the Data Model: tick “Add this data to the Data Model” when you create it. For Lantern it gives 112 customers. Without the Data Model, =ROWS(UNIQUE(Orders[customer_id])) from the last lesson gives the same number.

Show Values As: shares instead of amounts

Right-click a value and choose Show Values As to replace each amount with a calculation on it. Microsoft lists, among others: % of Grand Total, % of Column Total, % of Row Total, % Of (a chosen base item), Difference From, % Difference From, Running Total In and the Rank options. The three percentage-of-total options answer different questions, and the formula cards below give each.

Which one is “% of column” depends on the layout: the same question needs % of Row Total if months run down the rows instead. Before you choose, say the question as “what share of X was Y” and check that the option divides by X. The wrong option still gives a tidy column of percentages that add up to 100% somewhere, which is why it goes unnoticed.

Grouping dates and numbers

A date field in Rows can show one row per day, which is rarely what you want. Right-click a date and choose Group, then under By choose Months (or Quarters, or another period); recent versions of Excel detect related time fields and group them for you. If the data span more than one year, select Years as well as Months, so that each row is one month of one year.

Numbers group the same way, into equal intervals: right-click an order_total row label, Group, Starting at 0, By 20, and the rows become $0–$20, $20–$40 and so on, the equal-width binning of B02. Bands of unequal width, such as Ana’s order-size bands, need a helper column with an approximate-match lookup (the lookups lesson), which then goes into Rows like any other field.

Sorting and filtering

Use the arrow on Row Labels or Column Labels to sort A to Z or Z to A, or right-click a cell and choose Sort, which sorts all the items at that level. To rank items by their totals, select a value in the Grand Total column and sort it. Month names typed as text would sort alphabetically (Apr, Jun, Mar, May); grouped dates sort in calendar order, and Excel’s built-in month and weekday custom lists, under More Sort Options, fix text months too.

Filters limit which records count. A field in the Filters area filters the whole PivotTable (channel = app, say), and the arrows on the labels filter rows or columns. A slicer does the same job with a panel of buttons that also shows what is selected: click in the PivotTable and choose Insert › Slicer. Slicers work on tables too, and one slicer can drive several PivotTables built from the same source through Report Connections.

Refresh and the pivot cache

A PivotTable doesn’t read the table cell by cell. It summarises a copy of the source data, the pivot cache; Microsoft’s developer documentation describes the PivotCache object as “the memory cache for a PivotTable report”. When the source changes, the PivotTable keeps showing the old figures until it is refreshed: right-click it and choose Refresh, press Alt+F5, or use Refresh All on the PivotTable Analyze tab for every PivotTable at once. PivotTable Options › Data › “Refresh data when opening the file” refreshes on opening.

Microsoft is adding an Auto Refresh option for PivotTables on data in the same workbook, but when this lesson was checked it was available only to members of the Microsoft 365 Insider programme; don’t count on it. And refresh can only see what the source range covers. A PivotTable built on A1:M232 ignores orders pasted into row 233, refresh or not; built on the table Orders, it includes them, because the table grows. An old PivotTable can be pointed at a table with Change Data Source.

PivotCharts and GETPIVOTDATA

A PivotChart (Insert › PivotChart) charts a PivotTable’s summary, and the charts lesson covers which chart to choose. To use a PivotTable’s number in an ordinary formula, type = and click the value cell: Excel writes a GETPIVOTDATA formula such as =GETPIVOTDATA("order_total",$A$3,"channel","web"), which finds the value by its labels rather than its position, so it survives a rearranged layout. It returns only data the PivotTable shows, and #REF! if a filter hides it. You can switch the feature off with PivotTable › Options › Generate GetPivotData.

PivotTable or SUMIFS?

Choosing between a PivotTable and formulas
PivotTableSUMIFS, COUNTIFS and AVERAGEIFS

New categories in the dataAppear by themselves at refreshNeed a new row or column of formulas
UpdatingOnly when refreshedImmediately, like any formula

Use a PivotTable to explore, to answer one-off questions and for summaries whose categories may change. Use a summary table of formulas for a fixed report or dashboard that must update the instant the data do, that must show a category even when it has no records, or whose layout matters. Whichever you use, reconcile: the PivotTable’s grand total must equal =SUM(Orders[order_total]), $9,096.15 over 231 orders, and any cell you are about to quote should match a SUMIFS. A mismatch means a stale cache, a source range that stops short, or a filter you forgot.

Common mistakes

  • “The PivotTable shows the latest data.”

    It shows its cache as of the last refresh. After correcting or adding data, refresh (Alt+F5, or Refresh All), and build it on an Excel table so that new rows are inside the source range.

  • “Count of a column counts the rows.”

    Count counts non-empty values, as COUNTA does. Count of rating counts rated orders only. Count a field that is never blank, such as an id, to count records, and use Distinct Count (with the Data Model) to count different customers.

  • “My totals show as Count, so the PivotTable is broken.”

    A value field with any text or blanks in it starts as Count. Usually the numbers are stored as text: clean the column (VALUE, as in the last lesson), refresh, and switch the field to Sum.

  • “Any percentage option will do.”

    % of Grand Total, % of Row Total and % of Column Total divide by different bases and answer different questions. Say the question as “what share of X is Y”, and check that the option divides by X in your layout.

  • “A big number in a PivotTable is a trend.”

    A sum can be one record. May’s high value is one office order. Check the records behind a surprising cell (filter the table, or sort by value) before you explain it.

  • “If the PivotTable is right, I don’t need to check it.”

    Reconcile its grand total with a SUM of the source and spot-check a cell with SUMIFS. Stale caches, short source ranges and forgotten filters all produce totals that look perfectly reasonable.

In practice

Lantern’s monthly review. Ana keeps one PivotTable sheet on the Orders table, with slicers for channel, region and subscription. At each month-end she pastes the cleaned orders into the table, clicks Refresh All, and checks that the grand total equals the SUM of order_total before she reads anything else. Questions that come up in the meeting (“what about the app in the North?”) are answered by clicking a slicer, not by writing new formulas.

A bookshop’s buying decisions. Cobble Lane Books, a fictional bookshop, exports its till data each week. The buyer’s PivotTable puts category in Rows and weeks in Columns, with Sum of sales and % of Row Total, to see whether each category’s sales are rising through the term; categories that appear for the first time (a new author’s series) show up at the next refresh without anyone editing a formula.

From exploration to a fixed report. Once the questions settle, an analyst often rebuilds the few figures that matter with SUMIFS on a report sheet: fixed layout, every category shown even when it is zero, instant updates. The PivotTable stays as the exploring tool and as the check: each month, the report’s SUMIFS figures must equal the PivotTable’s. The dashboards lesson builds on this.

Customers, not orders. A coffee-subscription start-up (fictional) reports “active customers” each month. Its analyst builds the PivotTable with “Add this data to the Data Model” ticked, puts the month in Rows and the customer id in Values as a Distinct Count, and puts Count of order id beside it. The gap between the two columns is the repeat buying the founders want to see, and it would vanish if someone counted ids without the Data Model.

Summary

  • A PivotTable groups the records of its source by the fields in Rows and Columns and aggregates a field in Values; Filters limit which records count.
  • Build it on an Excel table of clean data: one header row of unique labels, one record per row, no totals inside the data.
  • Numeric fields start as Sum; a field with text or blanks starts as Count, which counts non-empty values, like COUNTA. Distinct Count needs the Data Model.
  • Show Values As gives % of Grand Total, % of Row Total and % of Column Total; choose the one whose base matches the question’s “share of what”.
  • Group dates by months (and years), group numbers into equal intervals, and sort by labels or totals.
  • A PivotTable summarises its cache: refresh after the data change, and build it on a table so new rows are included.
  • Every value cell is a conditional aggregate: reconcile the grand total with SUM and spot-check cells with SUMIFS; use formulas for fixed, always-live reports.

Terms introduced

PivotTable
Excel’s interactive summary table: it groups the records of a source by the fields placed in its Rows and Columns areas and aggregates a field placed in its Values area, rebuilding when fields are moved.
Pivot cache
The copy of the source data that a PivotTable summarises; the PivotTable shows new or corrected data only after it is refreshed.
Slicer
An Excel panel of buttons that filters a table or PivotTable and shows which items are selected; one slicer can control several PivotTables that share the same data source.
Distinct count
The number of different values in a field, counting each value once however many records share it, such as the number of customers rather than orders.
