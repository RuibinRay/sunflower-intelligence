Lookups: VLOOKUP, INDEX and MATCH, XLOOKUP

Bring a value from one table into another by matching a key: a product’s cost from a price list, a delivery charge from a table of bands. Learn VLOOKUP, INDEX and MATCH, and XLOOKUP, when to match exactly and when approximately, and how to find out why a lookup returns #N/A or, worse, a wrong answer.

About 70 minutes

Before you start

You will be able to

  • Use VLOOKUP with an exact match to bring a value from a lookup table into a list, and explain why leaving out its fourth argument is a trap.
  • Build INDEX and MATCH lookups, including lookups to the left of the key and two-way lookups by a row and a column label.
  • Use XLOOKUP and XMATCH with a not-found value, match modes and search modes, and state which versions of Excel have them.
  • Apply approximate-match lookups to band tables such as delivery charges, and test the boundaries of every band.
  • Diagnose lookups that return #N/A or a wrong value because of spaces, numbers stored as text, misspellings, missing keys or duplicate keys.

Review first

  • Cells, references and formulas — A lookup table must stay put when the formula is filled down, which takes absolute references such as $H$2:$L$12.
  • Functions, logic, text and dates — Lookups are combined with IF, IFNA, TRIM and VALUE, which that lesson introduces.
  • Datasets: rows, columns, records and variables — A lookup matches rows by a key; primary keys are defined there.

Fictional case A fictional coffee business founded by Ana Lim. It starts as a catering and barista-training service, opens its own cafés and an online shop for beans, and plans a canned cold brew.

The idea

Fictional case

Ana’s spring order sheet lists each order’s product and quantity, but not what the coffee cost Lantern. That is on Kilnworth Roasting’s spring price list: 11 products, each with its line, bag size, Lantern’s shop price and Kilnworth’s cost per item. To cost an order she needs the right unit cost beside it. Typing 231 costs by hand would take an afternoon and invite slips, and when Kilnworth raises its prices in the autumn every typed cost would be out of date.

A lookup formula does the job in one step. It takes the product named in the order row, finds that product in the price list and brings back the value in the same row of the cost column. Filled down the order sheet, it costs every order, and if the price list changes, every cost changes with it.

Every lookup has three parts. The lookup value is what you search for: the product in the order row. The lookup table is the range that holds the keys and the answers: the price list. The return column holds the answer you want: unit_cost. Excel searches the key column for the lookup value and returns the value from the same row of the return column, much as you find a word in a dictionary and read the definition beside it.

In the order sheet, column A holds the order id, B the product and C the quantity. In D2 Ana types =XLOOKUP(B2,$H$2:$H$12,$L$2:$L$12), which reads: look for B2 in H2:H12 and return the value in the same position of L2:L12. Order LC-10001 is two Gift Box Trios, so D2 shows $20.00. Filled down, B2 becomes B3, B4 and so on, while the dollar signs keep the price list where it is.

Excel offers three ways to write a lookup. VLOOKUP is the oldest and works in every version. INDEX with MATCH also works everywhere and is more flexible. XLOOKUP is the newest and the simplest to read, but among desktop versions only Excel for Microsoft 365, Excel 2021 and Excel 2024 have it. You will meet all three in other people’s workbooks, so this lesson teaches all three.

Each can match in two ways. An exact match returns a result only when it finds a key equal to the lookup value, and #N/A when it doesn’t: right for product names, order ids and customer numbers. An approximate match finds the band a number falls in: the row with the largest lower bound that is not above the value. That is right for delivery charges, quantity discounts and tax bands. Lantern’s July delivery rule (from B01) is a two-row band table: orders up to $35.00 pay $4.95, and orders over $35 travel free.

Key idea: A lookup needs a key that identifies one row

The price list must hold each product once: product is its primary key. If a key appears twice, every lookup function in this lesson returns the first match and ignores the second, without any warning, unless XLOOKUP is told to search from the last item. Check a key column for duplicates before you rely on lookups into it.

In depth

VLOOKUP

VLOOKUP (“vertical lookup”) searches down the first column of a range and returns a value from a column to its right. It takes four arguments.

VLOOKUP(lookup_value, table_array, col_index_num, [range_lookup])
ArgumentWhat it isIn Ana’s formula
lookup_valueThe value to find in the first column of the tableB2, the order’s product
table_arrayThe range holding the keys (first column) and the answers$H$2:$L$12, locked with $
col_index_numWhich column of the range to return, counting the first as 15, column L (unit_cost)
range_lookupFALSE (or 0) for an exact match; TRUE or left out for an approximate matchFALSE

So Ana’s VLOOKUP version is =VLOOKUP(B2,$H$2:$L$12,5,FALSE). It returns the same costs as her XLOOKUP. Without the dollar signs of an absolute reference, filling it down would slide the range to H3:L13, H4:L14 and so on, and the lower rows would stop finding the products near the top of the list.

Caution: Leave out the fourth argument and VLOOKUP approximates

If range_lookup is TRUE or missing, VLOOKUP assumes the first column is sorted from smallest to largest and returns the closest match below the lookup value. On an unsorted product list it returns some other product’s cost for some orders and #N/A for others, with no warning. Type FALSE (or 0) every time you want an exact match. Try it in the worksheet under Explore: delete ,FALSE and watch some costs change.

VLOOKUP has two more weaknesses. First, the lookup value must be in the first column of table_array, so it can’t return anything to the left of the key: to find an order id from a customer number, the customer column must come first. Second, the column number is a constant typed into the formula. If someone inserts a column for supplier codes between line and size_g, Excel widens the range to $H$2:$M$12 but leaves the 5 alone, so the formula now returns column L, which holds the price: Gift Box Trio comes back at $58.00 instead of $20.00. A column number larger than the range is wide gives #REF!.

HLOOKUP is the same function turned on its side: it searches across the top row of a range and returns a value from a row below, with the same fourth argument and the same default. You need it only for tables laid out sideways, such as a rate card with months across the top.

INDEX and MATCH

MATCH finds a position: =MATCH("Cold Brew Pack",$H$2:$H$12,0) returns 10, because Cold Brew Pack is the 10th item in H2:H12. INDEX returns what is at a position: =INDEX($L$2:$L$12,10) returns $8.50, the 10th value in L2:L12. Put together, =INDEX($L$2:$L$12,MATCH(B2,$H$2:$H$12,0)) finds the order’s product in column H and returns the cost from the same position in column L.

The pair fixes both of VLOOKUP’s weaknesses. The return range is separate from the key range, so it can lie to the left. And because both are ordinary references, inserting a column shifts them along with the data, so the formula keeps pointing at the cost. One MATCH can also feed several INDEX formulas, which matters in a large workbook.

Caution: MATCH’s default isn’t exact either

MATCH’s third argument, match_type, defaults to 1: the largest value less than or equal to the lookup value, in a list sorted from smallest to largest. 0 finds the first value exactly equal to the lookup value, in a list in any order, and −1 finds the smallest value greater than or equal to it, in a list sorted from largest to smallest. For keys, always type 0.

INDEX can also take a row number and a column number, which gives a two-way lookup: one MATCH finds the row, another the column. The table below counts Ana’s spring orders by month and channel. To fetch May’s web orders, =INDEX($B$2:$C$5,MATCH("May",$A$2:$A$5,0),MATCH("web",$B$1:$C$1,0)) returns 23. Point the two lookup values at cells holding a month and a channel, and the same formula answers any combination.

XLOOKUP and XMATCH

XLOOKUP keeps the lookup range and the return range apart, as INDEX and MATCH do, and matches exactly unless told otherwise. Its first three arguments are required.

XLOOKUP(lookup_value, lookup_array, return_array, [if_not_found], [match_mode], [search_mode])
ArgumentValues and meaning
lookup_valueThe value to find
lookup_arrayThe column (or row) to search
return_arrayThe column (or row) to return from, the same length as lookup_array; several columns return several values
if_not_foundWhat to show when nothing matches; left out, the result is #N/A
match_mode0 exact match (the default); −1 exact match or else the next smaller item; 1 exact match or else the next larger item; 2 wildcard match, where * and ? stand for any characters and ~ escapes them
search_mode1 search from the first item (the default); −1 search from the last item; 2 and −2 binary search, which needs the list sorted ascending or descending

Three of these options solve everyday problems. A not-found value makes a missing key visible: =XLOOKUP(B2,$H$2:$H$12,$L$2:$L$12,"not on price list"). Searching from the last item finds the most recent match in a list kept in date order: in Lantern’s events sheet, with event ids in column A and clients in column C, =XLOOKUP("Pier Nine Studio",$C$2:$C$77,$A$2:$A$77,,0,-1) returns EV-068, the client’s latest event (9 December), while searching from the first item returns EV-003. And a return range of several columns brings back several values at once: =XLOOKUP("Cold Brew Pack",$H$2:$H$12,$I$2:$L$12) returns the line, size, price and cost, which spill into four cells side by side.

XLOOKUP also works on tables laid out across a row, so it replaces HLOOKUP too. XMATCH is MATCH with XLOOKUP’s arguments: it returns a position, matches exactly by default, and takes the same match and search modes. Microsoft’s own two-way example combines them: =INDEX($B$2:$C$5,XMATCH("May",$A$2:$A$5),XMATCH("web",$B$1:$C$1)) gives the same 23 as the INDEX and MATCH version.

Standards: Which versions have XLOOKUP and XMATCH

XLOOKUP and XMATCH work in Excel for Microsoft 365, Excel 2024 and Excel 2021, on Windows and on Mac. Microsoft states that XLOOKUP is not available in Excel 2016 or Excel 2019. VLOOKUP, HLOOKUP, INDEX and MATCH work in all of these. If a workbook will be opened by someone on an older version, build its lookups with INDEX and MATCH.

Approximate match: lookups into bands

A band table lists the lower bound (“from”) of each band in its first column, sorted from smallest to largest, with each band’s result beside it. An approximate match returns the result of the last band whose lower bound is not above the lookup value. The formula card below states the rule; the figure above shows it working.

With the order value in B2, any of three formulas returns the delivery charge: =VLOOKUP(B2,$F$2:$G$3,2,TRUE), =XLOOKUP(B2,$F$2:$F$3,$G$2:$G$3,,-1) (match mode −1: exact match or else the next smaller item) and =INDEX($G$2:$G$3,MATCH(B2,$F$2:$F$3,1)). The size band is the same idea with four rows: =XLOOKUP(B2,$I$2:$I$5,$J$2:$J$5,,-1).

The boundary needs care. B01’s rule is free delivery on orders over $35, and order values are whole cents, so the free band starts at $35.01 and an order of exactly $35.00 pays $4.95. Typing 35 in the table would hand a $35.00 order free delivery that the rule doesn’t give. Test every boundary with a value just below it, one exactly on it and one just above it: 34.99, 35.00 and 35.01 here. Test the bottom too: a value below the first lower bound, such as a −12.60 refund, has no band and returns #N/A.

Keep band tables sorted. Microsoft documents that VLOOKUP’s approximate match and MATCH with match_type 1 assume the first column is sorted from smallest to largest, and that XLOOKUP’s binary search modes give invalid results on unsorted data. XLOOKUP’s default search reads every item, so its match_mode −1 copes with an unsorted table, but a sorted table is the one a reader can check at a glance. Why not use IF? =IF(B2>35,0,4.95) works for two bands, but four size bands need nested IFs with the thresholds buried inside the formula, while a band table puts the rule where anyone can read and change it.

Why a lookup returns #N/A, or the wrong answer

An #N/A from an exact-match lookup is an error value that means “no key equal to this one”. Microsoft’s list of the usual causes covers four of the rows below: the value really isn’t there, the two sides hold different data types, there are extra spaces, and the match type is wrong. The wrong match type, the unlocked range and the duplicate key are the dangerous ones, because they can give a plausible number instead of an error. Two tests help with types: =ISTEXT(B2) is TRUE when B2 holds text, and =ISNUMBER(B2) is TRUE when it holds a number.

Handle a genuine miss on purpose. XLOOKUP’s if_not_found, or =IFNA(VLOOKUP(B2,$H$2:$L$12,5,FALSE),"not on price list") in versions without XLOOKUP, labels the rows that need attention. Don’t wrap lookups in IFERROR to make the errors go away: IFERROR also hides a #REF! or #VALUE! from a broken formula, and a cost replaced by 0 or a blank understates the product cost without anyone noticing. The functions-and-logic lesson compares IFERROR and IFNA.

Duplicate keys deserve a check of their own. Microsoft’s developer reference for VLOOKUP says that when two or more values in the first column match, the first value found is used; MATCH with 0 finds the first value exactly equal to the lookup value; and XLOOKUP searches from the first item unless told otherwise. A price list with House Blend 250g twice, at two costs, would return the first cost for every order, right or not. Fill =COUNTIF($H$2:$H$12,H2) down beside the key column: any result above 1 is a duplicate key to resolve (B02’s duplicates lesson covers how).

Use XLOOKUP when everyone who opens the workbook has a version that supports it; use INDEX and MATCH when someone may open it in Excel 2019 or earlier; and learn to read VLOOKUP, because it fills the workbooks you will inherit. Whichever you write, check the match type, lock the table range and test a key you know.

Common mistakes

  • “VLOOKUP finds the matching row.”

    Only if you ask for an exact match. Its fourth argument defaults to TRUE, an approximate match that assumes a sorted first column; on an unsorted list it returns plausible wrong values without any error. Type FALSE every time you look up a key, or use XLOOKUP, which is exact by default.

  • “The formula worked in the first row, so it works all the way down.”

    Without dollar signs on the table range, filling down slides the range: by row 10 it starts eight rows below the top of the list, and the products above it can no longer be found. Lock the table range ($H$2:$L$12) and check a row near the bottom.

  • “#N/A means the product isn’t on the list.”

    Often it is there, but stored differently: a trailing space, a number stored as text, or a slightly different spelling. Test with LEN, ISTEXT and ISNUMBER, and fix the key. Only when the key really is missing should you flag it with if_not_found or IFNA.

  • “Wrap it in IFERROR and the errors go away.”

    They go away from view, not from the data. IFERROR replaces every error, including the #REF! of a broken formula, and a cost of 0 makes totals look complete when they aren’t. Use IFNA or if_not_found with a visible message, and count the rows that carry it.

  • “Over $35 means the band starts at 35.”

    An approximate match puts a value equal to a lower bound in that band, so a band starting at 35 includes $35.00. For “over $35” in whole cents the band starts at 35.01. Test every boundary with a value just below, exactly on and just above it.

  • “A lookup returns every matching row.”

    VLOOKUP, MATCH and XLOOKUP return one match: the first, unless XLOOKUP is told to search from the last. If the key column has duplicates, the others are ignored. Check the key column with COUNTIF before relying on it, or use FILTER (next lesson) when you really want every match.

In practice

Kilnworth’s autumn prices. When Kilnworth sends its autumn list, Ana pastes it over the spring one, and every cost in the order sheet updates at once. She adds “not on price list” as XLOOKUP’s not-found value, so a product Kilnworth has renamed or dropped shows up immediately instead of costing nothing. To see which costs rose, she keeps the spring list beside the new one and looks each product up in both, a side-by-side comparison that would take an hour to type by hand.

A hotel’s rate card. Ridgeline Lodge, a fictional hotel, prices rooms by room type (rows) and season (columns). Its booking sheet finds each booking’s nightly rate with a two-way INDEX and MATCH, so the revenue manager can change one cell of the rate card and see every quote move. Because the reservations team uses an older version of Excel, the workbook avoids XLOOKUP.

Commission tiers. A sales team paid 2% commission on monthly sales of up to $10,000, and 3% on all its sales in a month when they are above $10,000, uses a band table and an approximate match, not a nested IF. Before payroll, the analyst runs the boundary test ($9,999.99, $10,000.00 and $10,000.01) against the policy wording, because “above $10,000” and “from $10,000” differ by exactly the cent the test checks.

Matching payments to invoices. A finance team looks up each bank payment’s invoice number in the invoice list with XLOOKUP and “unmatched” as the not-found value. The unmatched rows are the reconciliation’s to-do list: typos in references, payments covering two invoices, or money that belongs to someone else. This is B02’s referential-integrity check done with a lookup: every key in one table should point to a row in the other.

Summary

  • A lookup finds a lookup value in the key column of a lookup table and returns the value from the same row of a return column; fill it down with the table range locked by $.
  • VLOOKUP needs FALSE for an exact match, can’t look left of its key, and breaks when a column is inserted; INDEX with MATCH (match_type 0) fixes both weaknesses and works in every version.
  • XLOOKUP is exact by default, takes a not-found value, can search from the last item and can return several columns; it and XMATCH need Excel for Microsoft 365, 2021 or 2024.
  • Approximate matching returns the result of the last band whose lower bound is not above the value; keep band tables sorted and test every boundary (“over $35” starts at 35.01).
  • #N/A usually means a key stored differently (spaces, text versus number, spelling), not a missing one; diagnose with LEN, ISTEXT and ISNUMBER and fix the key.
  • Handle genuine misses with IFNA or if_not_found and a visible message; IFERROR with 0 hides broken formulas and understates totals.
  • Lookups return the first match only, so check key columns for duplicates with COUNTIF.

Terms introduced

Lookup value
The value a lookup formula searches for, such as the product named in an order row.
Lookup table
A range holding the keys a lookup searches and the values it can return, such as a price list or a table of bands.
Exact match
A lookup that returns a result only when it finds a key equal to the lookup value, and #N/A when it doesn’t.
Approximate match
A lookup that, when no key equals the lookup value, returns the row of the largest key below it (or, in some modes, the smallest key above it); used with band tables sorted by their lower bounds.
Two-way lookup
A lookup that finds a value by its row label and its column label at once, for example with INDEX and two MATCH functions.
Spill
What a formula that returns several values does in Excel for Microsoft 365, Excel 2021 and Excel 2024: the results fill the neighbouring cells, the spill range, starting from the formula’s cell.
