Encoding categorical variables

Turn categories such as region, room type or roast into numbers a model can use, without inventing an order or a distance the categories don’t have. Learn one-hot and dummy coding, ordinal, frequency and target encoding, and how to handle the dummy-variable trap, rare and unseen categories, and variables with thousands of values.

About 90 minutes

Before you start

You will be able to

  • Explain why most models need categorical variables converted to numbers, and how arbitrary codes mislead linear and distance-based models.
  • Encode a nominal variable with one-hot encoding or dummy coding, and calculate how many columns an encoding creates.
  • Explain the dummy-variable trap and decide when dropping a reference category is necessary and when keeping every column is better.
  • Apply ordinal, frequency and target encoding, and state the assumption each makes.
  • Calculate smoothed and out-of-fold target encodings that avoid data leakage.
  • Handle rare categories, categories unseen at prediction time and high-cardinality variables.

Review first

  • Normalisation and standardisation — You need training and test sets and the rule that every data-dependent step is fitted on the training set only.
  • Datasets: rows, columns, records and variables — You need the difference between nominal and ordinal variables.
  • Text cleaning and consistent categories — Spelling variants must be consolidated before encoding, or each variant becomes a category of its own.

The idea

Fictional case

Lantern Coffee Co. wants to know which first-time customers are likely to order again within 60 days, so that it can send a welcome offer to those who probably won’t. Lantern’s analyst, Jun Park, has the online-shop export, with each order’s region, channel and subscription status, and he knows which customers came back. His first model is a logistic regression, which multiplies each input by a coefficient, adds the results and turns the total into a probability. It stops at the first column: it can multiply 1.5 by a dollar amount, but not by “North”.

Most models do arithmetic on their inputs. Linear and logistic regression multiply and add; k-nearest neighbours and k-means measure distances. A categorical variable, whose values are labels, must therefore be turned into numbers before these models can use it. That conversion is categorical encoding. The difficulty is that numbers carry meaning of their own, order and distance, which the labels may not have.

Numbers that invent an order

The quickest encoding numbers the categories, usually in alphabetical order: once the spelling variants are consolidated, Lantern’s five regions become Central 0, East 1, North 2, South 3 and West 4. This is label encoding. Now look at what a model does with it. A logistic regression gives region a single coefficient, so the effect of region has to rise or fall in equal steps from Central through East, North and South to West, an order that comes from the spelling of the names. A nearest-neighbour model concludes that a Central customer is four times as far from a West customer as from an East one. None of that is true of the regions. Region is a nominal variable: its categories have no order, so its code numbers must not have one either.

One-hot encoding

One-hot encoding replaces the column with one new 0/1 column per category. Each row has a 1 in the column for its own category and 0 everywhere else.

Now each region gets its own coefficient, free to take any value, and every pair of regions is the same distance apart: two rows from different regions differ in exactly two columns, so their Euclidean distance is 12+12=2≈1.41\sqrt{1^2 + 1^2} = \sqrt{2} \approx 1.4112+12​=2​≈1.41. No order has been invented. The price is width: five columns instead of one.

A variable with only two categories needs only one column. Lantern’s subscription flag becomes 1 for “yes” and 0 for “no”, and its channel becomes 1 for app and 0 for web. A second column would add nothing, because it would always equal 1 minus the first.

Ordered categories

Some categories do have an order. Lantern’s catalogue describes each coffee’s roast as light, medium or dark, which is an ordinal variable. Ordinal encoding numbers the categories in their true order, light 1, medium 2 and dark 3, and keeps them in one column. It preserves the order, but it also asserts something the labels don’t: that the step from light to medium is the same size as the step from medium to dark.

Many categories

Some variables have hundreds or thousands of categories: postcodes, product codes, travel-agent codes. This is high cardinality (the cardinality of a variable is the number of distinct values it takes). One-hot encoding would create thousands of columns, mostly zeros, with many categories seen only once or twice. The alternatives replace each category with a single number learned from the training data, such as how common the category is or the average outcome for that category. They are compact and often effective, and the second kind can leak the answer into the model if it is computed carelessly.

Key idea: Four questions before you encode

Is there a real order among the categories? How many categories are there, and how many rows does each have? Does the model need one column fewer than the number of categories, or all of them? And has every encoding been learned from the training set alone?

In depth

One-hot encoding in detail

A variable with kkk categories becomes kkk columns, and in every row they add up to exactly 1. Geometrically, each category sits at its own corner, and all the corners are 2\sqrt{2}2​ apart, which is why one-hot encoding suits distance-based methods. Most of the entries are 0, so software often stores the result in a sparse format that records only where the 1s are.

Two practical points. First, clean before you encode. The region column of the lantern-orders export spells regions several ways (different capitals, stray spaces, abbreviations, typing errors), and an encoder treats every variant as a separate category, so “North”, “north” and “North ” would each get a column. Consolidate the variants first, as in the text-and-categories lesson. Second, know your tool’s defaults. In pandas, pd.get_dummies(df, columns=['region'], dtype=int) keeps all kkk columns unless you set drop_first=True, and without dtype=int it returns True/False columns. In scikit-learn, OneHotEncoder learns the categories when it is fitted and keeps all of them unless you set its drop option.

The dummy-variable trap

Most regression models include an intercept, which is a coefficient multiplied by a column of 1s. The kkk one-hot columns of a variable also add up to 1 in every row, so together they exactly reproduce the intercept’s column. One column is a perfect combination of the others: perfect multicollinearity. This is the dummy-variable trap. The data can no longer decide between infinitely many sets of coefficients that make identical predictions, and least squares has no unique answer, because the matrix it must invert is singular.

An example makes it concrete. In a sample of off-season bookings, the fictional Harborview Hotel’s average nightly rates by room type are Standard $140, Deluxe $185, Family $210 and Suite $320. With room type as the only predictor, a regression predicts each type’s average rate. Both rows of the next table do that exactly, and so does any row in which a constant is added to the intercept and subtracted from all four room coefficients.

Each prediction is the intercept plus the coefficient of the booking’s room type: 0 + 140 = 100 + 40 = 140 for a Standard room, and so on.

The cure is to drop one of the kkk columns. The category without a column becomes the reference category (also called the baseline), and the k−1k - 1k−1 remaining columns are called dummy variables. The intercept is then the reference category’s prediction, and each dummy’s coefficient is the difference between its category and the reference.

Dummy coding of room type with two different reference categories (fictional)
ReferenceInterceptStandardDeluxeFamilySuite
Standard140—+45+70+180
Deluxe185−45—+25+135

A Suite is predicted at 140 + 180 = 185 + 135 = $320 either way.

Changing the reference changes every coefficient and no prediction. Choose a reference that makes the comparisons useful: the largest category, which gives the most stable comparisons, or a natural baseline such as the standard room, customers without a subscription, or the web channel. Statistics packages usually create dummy variables automatically and pick a default reference, often the first category in alphabetical order; check which one they picked and say so when you report coefficients.

When to drop a column, and when not to

  • Drop one (use k−1k - 1k−1 dummies) for an unpenalised linear or logistic regression with an intercept, the classic statistical model whose coefficients you want to read. With several categorical variables, drop one category from each.
  • Keep all kkk for penalised models such as ridge and lasso regression. The penalty already makes the solution unique, and dropping a column makes one category special: scikit-learn’s documentation warns that it breaks the symmetry of the representation and can bias penalised linear models.
  • Keep all kkk for tree-based models, which never invert a matrix. A benchmark study by Pargent and colleagues (2022) found one-hot encoding performed slightly better than dummy coding with nonlinear regularised models such as random forests and gradient boosting.
  • Keep all kkk for distance-based methods. With k−1k - 1k−1 dummies the reference category sits at the origin, 1 unit from every other category, while the others stay 2\sqrt{2}2​ apart from each other: the reference becomes artificially close to everything.

The defaults reflect this: both OneHotEncoder and get_dummies keep every column unless you ask them not to. Dropping a column is a requirement of one family of models, not a rule of encoding.

Ordinal encoding and its assumption

Ordinal encoding keeps an ordered variable in one column of integers. In a linear model that column gets one coefficient, so the model assumes equal steps: light to medium moves the prediction exactly as much as medium to dark. If that is implausible, use one-hot encoding instead, which gives each level its own effect and ignores the order, or use numbers with real meaning. Lantern’s size_g column is already numeric (250, 480, 750 or 1,000 grams); recoding it as 1, 2, 3 and 4 would throw away the actual gaps between pack sizes.

The order must come from you. Software that isn’t told the order usually numbers categories alphabetically: scikit-learn’s LabelEncoder, for instance, numbers “paris”, “paris”, “tokyo” and “amsterdam” as amsterdam 0, paris 1 and tokyo 2. For roast that gives dark 0, light 1 and medium 2, which scrambles the order. In scikit-learn, pass the order explicitly: OrdinalEncoder(categories=[['light','medium','dark']]).

Label encoding of nominal variables

Label encoding gives a nominal variable arbitrary integer codes, as in the region example. For linear models it forces one straight-line effect along a meaningless order; for distance-based models it invents distances. Tree-based models are harmed less, because a tree can isolate a category with several splits, but each split can only separate codes above a threshold from codes below it, so useful groupings may need many splits. Pargent and colleagues argue that integer encoding is acceptable, if at all, only for tree-based models, and in their benchmark it did not perform well even with gradient boosting. scikit-learn’s documentation states that LabelEncoder is meant for encoding target labels, not input features.

Frequency encoding

Frequency encoding replaces each category with its share of the training rows, nc÷nn_c \div nnc​÷n. It needs one column whatever the number of categories, and it captures how common a category is, which is sometimes predictive in itself (popular products may be returned less often). Two categories with the same frequency become indistinguishable, and the shares must be computed on the training set and reused unchanged. A benchmark summarised by Pargent and colleagues found that it performed well in many cases.

Target encoding

Target encoding replaces each category with the average value of the target variable for that category in the training data. For a yes/no target coded 1 and 0, that average is the proportion of 1s. It also needs one column however many categories there are, and it puts the category’s relationship with the outcome directly into the feature. Micci-Barreca (2001) set out the method as a preprocessing step for high-cardinality variables, based on empirical Bayes estimation, and scikit-learn has provided it as TargetEncoder since version 1.3.

The danger is data leakage. Each training row’s own outcome is part of its category’s average, so the feature partly contains the answer. In the extreme, a category with a single training row is encoded as that row’s own outcome, and the model learns to trust a feature that is perfect in training and useless on new data. Three safeguards work together:

  • Smoothing.   • Out-of-fold encoding (cross fitting). Split the training set into folds and encode each fold using averages computed from the other folds only, so that no row’s own outcome enters its encoding. scikit-learn’s TargetEncoder does this inside fit_transform, with five folds by default; its documentation notes that fit followed by transform does not use cross fitting and can leak.
  • Test and new data are encoded with averages learned from the whole training set, never from their own outcomes, which are unknown at prediction time anyway. A category never seen in training gets the overall training average.

Rare and unseen categories

A category with only a handful of training rows gives an unreliable coefficient or encoding. A common remedy is to group rare categories into a single “Other” category, using a threshold set on the training data, such as fewer than 10 rows. scikit-learn’s encoders can do this with the min_frequency and max_categories options, which combine infrequent categories into one output.

Categories also appear after a model is built: a new delivery region, a new product, a new degree programme. Decide in advance what happens. scikit-learn’s OneHotEncoder raises an error by default; with handle_unknown='ignore' it encodes the new category as all zeros; with handle_unknown='infrequent_if_exist' it puts it in the “Other” column if there is one. Beware the combination of dummy coding and “ignore”: all zeros is exactly how the reference category is encoded, so an unseen region would silently be treated as the reference region.

High cardinality

Postcodes, product codes and customer numbers can have thousands of values. One-hot encoding them creates thousands of sparse columns, most categories are rare, and new values keep arriving. The usual strategies, often combined, are:

  • Move up a level. Postcode becomes district or region; product code becomes product line. Micci-Barreca’s scheme can also blend statistics across levels of such a hierarchy, for example ZIP codes.
  • Group the rare values into “Other”, then one-hot encode what remains.
  • Use frequency or target encoding, fitted on the training set with smoothing and out-of-fold estimates.
  • Leave identifiers out. customer_id and order_id are keys that pick out a row (a primary key identifies each row), not descriptions of it. A model given customer_id can memorise individual customers and has nothing to say about a new one.

Missing categories

A blank category can be encoded as a category of its own, such as “Not stated”, when the fact that it is missing may carry information. pandas’ get_dummies adds a column for missing values only if you set dummy_na=True; otherwise a missing value becomes a row of zeros. scikit-learn’s TargetEncoder treats missing values as another category.

Fit encoders on the training set

Every encoder learns something from data: the list of categories, the reference category, the frequencies, the target averages. Like a scaler, it is fitted on the training set and applied unchanged to the test set and to new data. A category list taken from all the rows would quietly tell the training process about categories that exist only in the test set; target averages taken from all the rows put the test outcomes into the training features, which is leakage of the most damaging kind.

Common mistakes

  • “Numbers are numbers: code the categories 1, 2, 3.”

    Arbitrary codes for a nominal variable invent an order and distances. A linear model is forced to give the categories one straight-line effect along that order, and a nearest-neighbour model treats alphabetically distant categories as dissimilar. Use one-hot encoding, or frequency or target encoding when there are many categories.

  • “Always drop one dummy column.”

    Dropping a column is needed for unpenalised regression with an intercept. Penalised models, tree-based models and distance-based methods work better with all kkk columns, and dropping one makes the reference category special. Drop deliberately, for the model that needs it.

  • “Target encoding is just a group average, so compute it on all the data.”

    The average contains each row’s own outcome, and computed on all rows it contains the test outcomes too. Fit it on the training set, encode training rows out-of-fold, smooth small categories, and encode test and new rows with the training averages.

  • “Ordinal encoding is safe for anything with an order.”

    It assumes equal steps between levels, and tools that aren’t told the order use alphabetical order: dark, light, medium. Supply the order explicitly, and switch to one-hot encoding or meaningful numbers when equal steps are implausible.

  • “Encode every column, including the IDs.”

    Identifiers such as customer_id pick out rows; they don’t describe them. Encoded, they let a model memorise individual customers and say nothing about new ones. Leave them out, and treat other high-cardinality variables by grouping or with fitted frequency or target encodings.

  • “New categories won’t turn up.”

    New regions, products and programmes appear all the time. Decide beforehand: raise an error, map them to “Other”, or use the overall training average for target encoding. With dummy coding, encoding an unknown category as all zeros silently treats it as the reference category.

In practice

Jun finishes his reorder model by writing down an encoding plan, because the model is only as reusable as that plan. Region is consolidated to its five valid values and one-hot encoded; channel and subscription become single 0/1 columns; roast is ordinal-encoded in the order light, medium, dark after a quick check that reorder rates move steadily across the three. For a penalised logistic regression used for prediction, he keeps all five region columns. When Ana asks “how much more likely are Western customers to reorder than Northern ones?”, he fits an unpenalised version with North as the reference category, so that each coefficient answers a question in that form. Everything is fitted on the training months and stored in the pipeline, including an “Other” rule for any new delivery region.

At the Harborview Hotel, a cancellation model uses the booking channel (five values), the guest’s country (nine countries once codes and names are made consistent, several with only a handful of bookings) and, for travel-agent bookings, an agent code with hundreds of values. Channel is one-hot encoded. Countries with fewer than a set number of training bookings are grouped into “Other” before one-hot encoding, so that a country with two bookings can’t produce a wild coefficient. The agent code is target-encoded on the cancellation outcome, out-of-fold and smoothed, and new agents get the overall training cancellation rate. The analyst also reports how many test bookings had an agent never seen in training, because those predictions rest on the overall rate alone.

At Northfield University, the planning office uses programme in a model that forecasts how many students will need extra tutoring. When a new degree programme is approved, the encoder would raise an error on its first students, or, with dummy coding and unknown categories ignored, silently treat them as the reference programme. The office therefore decides in advance that new programmes are encoded as “Other” until a full year of data exists, records that decision in the cleaning log, and refits the encoder and the model at the start of each academic year.

Summary

  • Most models need numbers; categorical encoding converts labels into numbers without inventing an order or distances the categories don’t have.
  • One-hot encoding creates one 0/1 column per category and keeps every pair of categories equally far apart; a two-category variable needs only one column.
  • With an intercept, all k one-hot columns are perfectly collinear (the dummy-variable trap); unpenalised regression therefore uses k − 1 dummies and a reference category, while penalised, tree-based and distance-based methods usually keep all k.
  • Ordinal encoding suits ordered categories but assumes equal steps and needs the order supplied explicitly; label encoding of nominal variables misleads linear and distance-based models.
  • Frequency and target encoding use one column for any number of categories; target encoding must be fitted on the training set, computed out-of-fold and smoothed to avoid leakage.
  • Group rare categories, plan for categories unseen at prediction time, and leave identifiers out of the model.

Terms introduced

Categorical encoding
Converting the labels of a categorical variable into numbers that a model can use.
One-hot encoding
Encoding a categorical variable with k categories as k columns of 0s and 1s, with a 1 in the column of each row’s category.
Dummy variable
A 0/1 column that marks whether a row belongs to one category. With dummy coding, a variable with k categories is represented by k − 1 dummy variables plus a reference category.
Dummy-variable trap
The perfect multicollinearity that arises when all k one-hot columns of a variable are used together with an intercept, so the coefficients can’t be uniquely estimated.
Reference category
The category left without a dummy variable. The intercept describes it, and each dummy coefficient is a difference from it. Also called the baseline.
Ordinal encoding
Encoding an ordered categorical variable as integers that follow its order, in one column. It assumes equal steps between levels.
Label encoding
Giving each category an arbitrary integer code, often in alphabetical order. Misleading for nominal input variables in linear and distance-based models.
Frequency encoding
Replacing each category with its share of the training rows.
Target encoding
Replacing each category with the average value of the target variable for that category in the training data, ideally smoothed and computed out-of-fold.
High cardinality
A categorical variable with a very large number of distinct values, such as postcodes or product codes.
